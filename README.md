# 每日调查新闻与高保真语音播报系统 (NewsCast)

> 专为「早上睁眼只想用耳朵」设计的每日语音早报。
> 每天早晨 6:00 前自动抓取过去 24 小时的真实中文资讯，筛出跟个人决策有关的部分，生成一段 9~15 分钟的普通话播报：金句、一人公司案例拆解、AI 动态、一人公司动态、宏观大势、要闻简报、今天能做的一件事。**全部内容都在音频里，不用看任何文字**；页面上只留一个播放按钮和一张实时行情卡。

---

## 🌟 核心特性

1. **自动化采集与调度 (Python)**
   - **每日定时（反向利用排队延迟）**：GitHub 免费版定时任务到点只是「进队列」，等有闲置机器才真正开跑。实测 13 次，设定时刻与实际开跑稳定相差 3~5.5 小时——设 05:30，实际永远在 08:46 之后。所以把「发车时间」放到前一天深夜（北京 23:00 / 23:40 / 次日 00:20 三个兜底点），让延迟把它推进凌晨 2~5 点，早上 6 点前必定已生成并部署完毕。先成功的那个写入数据，后面的检测到当天已生成会自动跳过。
   - **播报归属日**：以北京时间 19:00 为日界。深夜生成的早报记到次日，这样早上打开看到的是「今天」这一期，而不是昨天的日期。
   - **行情实时补位**：网页顶部有一张「全球市场·最新收盘」卡，打开页面时由浏览器直接向东财拉取道琼斯、纳斯达克、标普500、上证、创业板、黄金的最新价与涨跌幅（涨红跌绿）。音频在前一晚生成，看不到最新一夜的变动，这张卡用来把这块补上。每次构建还会写一份收盘快照到 `docs/data/market.json`，实时接口连不上时自动退到快照，不会整块消失。
   - **六大板块全真实抓取**：
     - **每日金句**：一句发人深省的搞钱箴言。
     - **一人公司案例**：拆开看一个人在做的具体一件事，怎么转起来、卡在哪。
     - **全球 AI 动态**：36氪 / 极客公园 / 爱范儿等中文源，真实抓取，过「相关性闸门」后才进来。
     - **一人公司新闻**：V2EX 分享创造 / 创意节点（中文一手产品发布流）+ Hacker News 收入帖（作者自述定价、涨价的真实数字）+ Reddit r/SideProject 长正文，菜谱、装备、壁纸这类题材直接挡掉。所有源在 Actions 侧探活过（`tools/probe_sources.py`）；小红书、B站、Indie Hackers 实测不可用，原因见下文「案例为什么每天都有」。
     - **宏观大势**：把学习强国、参考消息、新浪财经三个源合并，剔除外事会见、军事冲突、体育文娱、人事表彰，只留跟个人决策有关的信号，归入「钱的价格 / 你的钱袋子 / 大家敢不敢花钱 / 生意好不好做 / 技术在往哪走」五个域，每条讲清「发生了什么、这意味着什么、你该怎么做」。**只有能在「这条新闻 → 对你的影响」之间建立因果的才进这一段**：评论稿、个股推荐、采购公告一律不进，关键词虽然命中但只是背景板的也不进。宁可一天只讲一条，也不硬凑五条。
     - **要闻简报**：剩下的国内 / 国际 / 财经要闻，分组、带编号逐条念标题，不解读。以前这里的做法是「加起来 N 条，念了只会占你时间，我就不念了」——说一次叫体贴，天天说就是偷懒。已经在大势那段讲过的条目会自动跳过，不会念两遍。
     - **喜马拉雅·10分钟新闻早餐**：当天有则播，无则跳过。
   - **生动有趣·技术小白友好**：术语全部大白话化；解读按标题里真实出现的信号词定向生成，匹配不上就整段不写，绝不拿万能话凑字数；结尾送一个今天就能动手的具体动作。

2. **高保真普通话语音合成 (Edge-TTS)**
   - 默认采用微软高保真新闻演播男声 `zh-CN-YunxiNeural`（云希，沉稳纪实播音风格），支持一键切换 `zh-CN-XiaoxiaoNeural`（晓晓）等。
   - 生成纯文本播报稿并自动过滤 Markdown 噪音字符，带有平滑标点停顿与自然语流。

3. **数据存储与标准 REST API**
   - 本地持久化使用轻量高效的 SQLite (通过 SQLAlchemy 异步引擎管理)。
   - 提供丰富端点：
     - `GET /api/reports/latest`：获取最新一期全量简报与音频元数据。
     - `GET /api/reports`：历史往期简报列表。
     - `POST /api/reports/trigger`：手动触发立即生成流水线（开发测试或实时抓取无需等待明早 6 点）。
     - `GET /api/status`：系统运行与调度状态。

4. **手机端 PWA 现代交互界面（以听为主）**
   - **只用听就够**：整期内容全部在音频里——金句、案例、AI 动态、一人公司动态、宏观大势、要闻简报、今天能做的一件事，不留「去页面查看」的尾巴。
   - **先报结构，再讲内容**：开场就说清今天一共几块、每块讲什么；每块开头报「第几块」「这块是什么」，块内再逐条编号。听众不看文字也能知道自己听到哪儿了、还有多少。
   - **不重复同一种说法**：开场、过渡、收尾、解读的连接词都按日期轮换，相邻两天不会落到同一句上。「先送你今天的一句话」「要我说」这种固定句式不再连着出现。
   - **章节跳转**：生成时按各段字数换算出时间点，页面上给出 10 个左右的章节（开场 / 金句 / 案例各段 / AI / 一人公司 / 大势 / 要闻 / 行动），点一下直接跳过去；播放时当前章节自动高亮。要闻那一块占三到四分钟，赶时间可以直接跳到最后。
   - **页面只留一眼能看的东西**：首屏是「按一下开始听」的大按钮，下面是实时行情卡；完整文字稿与原文清单收进折叠区，不听时再点开。
   - **响应式设计**：专为手机竖屏优化，适配 iPhone/Android 底部安全区域。
   - **PWA 离线支持**：内置 `manifest.json` 与 `sw.js` Service Worker，支持“添加到主屏幕”，秒变独立原生级 App。
   - **底部全局悬浮播放器**：
     - 实时进度拖拽与已播/总时长显示。
     - 快退 15 秒 / 快进 15 秒。
     - 0.75x、1.0x、1.25x、1.5x、2.0x 独立无损调速。
     - **Web Media Session API**：完美支持手机锁屏界面与系统通知栏后台控制（专辑封面、歌曲名、暂停/播放与跳段）。

## 🚀 快速启动

### 方式一：Windows 一键启动（推荐）

双击项目根目录下的 `run.bat`，或在 PowerShell 中执行：
```powershell
.\run.ps1
```
服务将在 `http://localhost:8000` 启动，浏览器打开即可使用。

### 方式二：手动命令启动

```bash
# 1. 激活虚拟环境 (已配置 uv)
.venv\Scripts\activate

# 2. 启动 FastAPI 服务
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 方式三：Docker 容器化部署

```bash
docker compose up -d --build
```

## 🎯 案例为什么每天都有

案例段是固定节目，不能靠当天正好碰上一条好帖子。

**先把一件事说清楚：案例不要求有人报收入。** 一段案例值不值得听，看的是
「这是什么、谁在做、怎么转起来、卡在哪」，不是「他赚了多少」。收入只是这条
故事里的一个信息点，有就讲，没有就不讲。把收入当入场券，会把大量能讲透的
素材挡在门外，只剩几条光有数字、没有产品描述的帖子——那才是「听完不知道
在讲什么」的真正来源。

所以开场只承诺「有个人在做一件具体的事」，不承诺「赚钱案例」。三档的实际
作用是**措辞**，不是准入门槛：

| 档位 | 什么情况 | 开场怎么说 |
|---|---|---|
| 有人付钱 | 原文写了付费用户数、订阅收入这类证据 | 「先看一个人在做的事」 |
| 没做成 | 原文明确写了没做成（没人用、放弃、关掉） | 「先看一个没做成的例子」 |
| 其余 | 上面两样都没有，但这条路讲得清 | 「今天讲一个具体做法」 |

**这三档不决定谁先上。** 2026-11-13 之前是按「有钱 → 没做成 → 做法」的顺序
依次试，等于又把收入变成了准入门槛：池子里只要有哪怕一条报过钱的，后面的
故事再好也轮不到。那天就是这么选出 Kapso 的——开源引擎、三千字正文、提到过
付费，但作者讲的是「我们在给企业做这套系统」，听众听不到一个人的处境。
同一批候选里还躺着一条「我受够了用 Excel 排行程，所以自己写了一个」。
现在合成一个池按分排，档位事后判，只影响措辞。

三档共用一条硬门槛：**「这是什么」必须说得具体**。「一个叫不出名字的在线工具」
「一个按月收费的服务，能获得某种持续提供的价值」——这类句子一律换下一条。
判据不是长度和格式，是**把抽象名词剥掉以后还剩几种字**：空壳剩九到十一种，
能讲清的剩二十种以上。

**行业不设限。** 代码不替听众判断「这门生意跟你有没有关系」——一门活讲不讲得清、
能不能拆出「他怎么干、卡在哪」，跟它属于哪个行业没关系。落到具体活儿上的
（小商家、教师、自由职业者）只做排序偏好，不做过滤。

候选有独立采集通道（`CASE_SOURCES`）：在 HN 上按「作者自述」的写法捞
（`paying customers`、`first customer`、`my SaaS`…），近 30 天窗口，
**不经过「今天有什么新闻」那道选题闸门**。第二条通道是 Show HN 的作品帖
（正文 240 字以上，有东西可拆）。第三条通道是 Reddit 的 `.rss`（见下）。
结果也一起送进翻译候选，所以「一人公司动态」那块的素材和案例段是同一批，
不各找一遍。

搜商业术语（MRR / revenue / pricing）没用——命中的九成是大厂财报。
搜「人怎么讲自己的生意」才有料。

**Reddit 是「讲得清」的解药。** HN 的帖子常常只有标题加两百字说明，
拆到「他卡在哪」就没词了；Reddit 那边是日记体，25 条里 22 条正文超 300 字、
中位数 978 字，是 HN 的两三倍，且天然第一人称（「我受够了用 Excel 排行程，
所以自己写了一个」）。固定拉 r/SideProject，再按天轮换 r/EntrepreneurRideAlong
（时间线最全）、r/microsaas（按月收钱）、r/sweatystartup（脏活累活起家，
不是技术人也能干）。

Reddit 对未认证请求限流很紧：连拉四个板块，后三个全回 429。所以是「固定一个
+ 轮换一个」，间隔 20 秒，429 等 30 秒重试一次，还不成就走人——案例池少一个
板块不影响今天，卡住会拖垮整条流水线。标题以问号结尾的直接跳过：那是「求建议」
不是「交结果」，拆出来是作者的困惑，不是他验证过的路。

**试过但接不了的源**（结论都写进 `tools/probe_sources.py`）：

| 源 | 实测 | 为什么不行 |
|---|---|---|
| 小红书 | 200，整页登录墙 | 没有对外接口，要登录态 + 每请求签名，风控专盯非 App 请求；服务器 IP 抓几次就要验证码，账号还有封号风险 |
| B站 | 412 | 搜索接口要 wbi 签名，算法会变，维护成本高于产出 |
| Indie Hackers | 404 | `/feed` 和 `/rss` 都不存在 |
| Reddit `.json` | 403 | 但 `.rss` 能过，这是接它的原因 |
| YouTube 频道 RSS | 200，描述 400~700 字 | 能拿到，但 RSS 只能按频道订阅、不给搜索；样本里全是教程（「怎么用某个工具」），不是「谁卡在哪」。要接得先人工攒一份「讲自己生意」的频道清单，暂不接 |

**小红书走人工投喂，但不用你复制正文。** 它的搜索和推荐流要登录态、要签名、
风控还专盯非 App 请求，自动发现这条路堵死。但**被分享出来的那一条是开放的**：
短链跳转后的详情页，正文完整写在 `og:description` 里，只要 UA 装成手机。

所以投喂只需要一个链接——`tools/xhs_shot.py` 负责把正文抓下来、整理段落、
写进 `cases/inbox/`。采集时当成正常候选参与打分，人工挑的加八分、
日期按当天算（不加的话它天天被自动抓的当天帖子压住，投了等于没投）。

实测两条：一条 973 字的小红书笔记拆出 8/11 栏；另一条 606 字的拆出 11/11 栏。

挑的时候按「讲得清」排序，不是按「有钱」排序：作者第一人称在讲自己的事、
有时间线（去年、后来、一开始）、有具体数字的，排在前面；正文最常见的
技术说明书反而靠后——同样的字数，前者能拆出动机和转折，后者只能拆出功能列表。

## 🔑 模型配置（可选，不配也能跑）

配了 DeepSeek 之后，节目会多出两样东西；不配则全流程照常，只是少了这两块：

| 有了模型 | 没有模型 |
|---|---|
| 抓 Show HN、Product Hunt 当天上新的英文产品，筛出与「一个人用 AI 解决具体问题」相关的，译成中文播报 | 这两块直接跳过，只用中文源 |
| 把一条真实帖子的原文读成四段：解决什么麻烦 / 用什么做的 / 怎么收钱 / 你能不能抄 | 只能照抄原句，遇到没写背景的帖子就是「作者没细说」 |

**生产环境**：仓库 → Settings → Secrets and variables → Actions → New repository secret，
名字填 `DEEPSEEK_API_KEY`，值填 `sk-` 开头那串。工作流已经接好，推一次就会自动带上。

**本地调试**：在项目根目录建一个 `.env`（已在 `.gitignore` 里，不会被提交）：

```bash
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
# 可选
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
```

一条硬约束：**案例里出现的每个数字都会回原文比对，找不到就整条作废、退回规则抽取**。
模型编一个看起来很合理的价格，听众照着试一次就会被现实打回来，这个代价比没有案例大得多。

### 这个仓库公开了，密钥会不会跟着公开？

不会。key 只存在两个地方，两个地方都不进 git：

- **GitHub Actions Secrets**：加密存储，只在 workflow 那一步注入成环境变量，
  日志里 GitHub 会自动把密钥值打码；代码里只出现 `${{ secrets.DEEPSEEK_API_KEY }}` 这个名字。
- **本地 `.env`**：已在 `.gitignore` 里。真正把 key 泄出去的常见原因不是开源，
  而是某次手滑 `git add -f .env` 或者临时改 `import` 路径——所以提交前扫一眼 `git status` 就够了。

Fork 这个仓库的人**拿不到你的 Secret**（GitHub 不会复制 Secrets 到 fork），
他们跑 Actions 时 `DEEPSEEK_API_KEY` 是空的，会自动降级成规则引擎模式，正常出节目。
想用完整效果，得自己申请一个 key 填进去——额度花的是他自己的。
