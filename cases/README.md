# 人工投喂的案例

这里放「自动抓不到、但值得讲」的案例。目前只有一个来源：小红书。

## 为什么需要这个目录

小红书是一人公司案例最密集的地方，但它接不进自动流水线：搜索和推荐流要登录态，
每次请求还要带签名；风控专盯「不是手机 App 发来的请求」，服务器 IP 抓几次就弹
验证码，账号还有封号风险。实测结论记在 `tools/probe_sources.py` 里。

**但有一条缝**：被分享出来的那条链接是开放的——短链 `xhslink.cn/o/xxxx` 跳转后
的详情页，正文完整写在 `og:description` 里，不用登录。前提是 UA 装成手机，
桌面 UA 会掉到登录页。

所以规则是：**自动发现不行，给你一条链接就能读**。
这就是这个目录存在的理由。

## 怎么投

最省事：在对话里直接发链接。

> 投这条 https://xhslink.cn/o/xxxxx

会用 `tools/xhs_shot.py` 把正文抓下来、整理好、写进这个目录。

也可以自己建文件，丢进 `cases/inbox/`，`.txt` 就行。格式：

```
我受够了用 Excel 排行程，所以自己写了个网站
链接：https://www.xiaohongshu.com/explore/xxxxx

第一行会被当成标题。正文直接粘，多少字都行。
```

三条规则：

1. **第一行是标题**，第二行起是正文
2. **「链接：」那一行可选**，有就按链接去重
3. 正文至少 120 字——短于这个拆不出「这是什么、卡在哪、今天能干啥」

## 播过之后

文件不用删。跨期去重会按链接（或内容指纹）记住它，不会播第二遍。
想让它重新进入候选，改一个字让指纹变掉即可——一般不需要。

## 日常用法

最省事的方式不是自己建文件，是在对话里直接说：

> 投一条小红书案例，内容如下：（粘贴）

会有人替你写进这个目录、提交、推送。下次生成时生效。
